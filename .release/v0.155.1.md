# codex-termux 0.155.1

Upstream: `rust-v0.155.1`.

## Fix

A model with an oversized message no longer hides the whole model list.

The message-size check (`model_messages.persistent_instructions` and
`model_messages.auto_review.node_repl_policy`, 8 KiB each) is a protection and
it stays. What changed is what it is allowed to decide: it used to run inside
deserialization, so one model with a long field made the WHOLE `/models`
response unreadable. The client then logged `failed to refresh available models`
and quietly served the catalog compiled into the binary or the on-disk cache —
where the newest models do not exist yet. The visible symptom was a model
disappearing from `/model` while the older ones stayed.

Now the check runs after the parse and drops only the model that fails, with a
warning that names its slug, the field and the byte count. If no model survives,
the response is still an error: there is no catalog to serve, and pretending
otherwise would be worse. The same rule applies to the on-disk cache, which is
the fallback used precisely when the network does not answer.
