# codex-termux 0.159.3-termux.1

Upstream: `rust-v0.159.3`.

## New upstream

- Merges upstream tags `rust-v0.159.2` and `rust-v0.159.3` into the Termux fork.
- TUI: compact session header (brand title shared with the status card), refined
  turn-tip gating with the usage notice, idle-pose replay animation and startup
  draft layout updates.
- App server: security-setup identity/notice payloads and the
  `SecuritySetupLoaded` app event; persistent-mode instructions gained the
  `persistent_execution_enabled` gate with the fork's size caps preserved.
- Workspace version moves to 0.159.3.

## Fork updates

- npm payload ships a static `codex-package.json` with `variant: "codex-termux"`
  (`layoutVersion: 1`, `target: "aarch64-linux-android"`,
  `entrypoint: "bin/codex.bin"`) beside `bin/` (`codex`, `codex-exec`,
  `codex.js`, `codex-exec.js`, `codex.bin`, `codex-code-mode-host`,
  `libc++_shared.so`). The daemon's variant check
  (`ensure_selected_variant_is_fork`) reads that manifest before reusing the
  launcher-selected binary: on Android `prepare()` reuses `CODEX_SELF_EXE`
  directly (PR #28) instead of staging a standalone package, so
  `remote-control start` works from npm. The complete-package staging layout
  (`vendor/<triple>/`, `codex-path/rg`, `codex-resources/`) is not part of
  this tarball: the Android daemon reuses the npm binary instead.
- Daemon isolation (config, login and sessions stay shared in `~/.codex`):
  the daemon only executes a managed binary that carries its own
  `codex-package.json` with `variant: "codex-termux"` (never an upstream or
  foreign-fork binary staged in the same packages tree), and owns the dedicated
  namespaces `packages/app-server-daemon-termux`, `app-server-daemon-termux/`
  (pid, lock, settings, logs, recovery) and `app-server-control-termux/`
  (control socket and startup lock).
- `platform_target()` knows `aarch64-linux-android` for daemon starts that
  reach the packaged layout; the Android branch keeps the npm-launcher
  selection as the last-resort managed install.
