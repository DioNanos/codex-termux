# v0.147.0

Android Termux release of `@mmmbuto/codex-cli-termux`, synchronized to upstream
OpenAI Codex `rust-v0.147.0`.

## Scope

- Integrates the upstream `rust-v0.147.0` stable release. Upstream tagged it one
  day after `0.147.0-alpha.13`; the two are siblings off the same parent and
  differ only in the workspace version, so this fork tracks the stable directly.
- Preserves browser login, real in-process V8 code-mode on Android, fork-owned
  update and installer channels, Android lock and PTY compatibility, and the
  bundled `libc++_shared.so` runtime with `RUNPATH=$ORIGIN`.
- Keeps the Termux release profile explicit: thin LTO, 16 codegen units, symbol
  stripping, and only the `deflate` and `time` features of `zip` — its default
  features pull bzip2/lzma/xz, which do not build in the Termux toolchain.
- Moves the Android V8 prebuild to `150.4.0`, matching the `v8 = "=150.4.0"` the
  upstream workspace now requires.

## Fixed

- **AGENTS.md created mid-session is now discovered** (issue #14). Discovery
  cached its result under the environment selection, which does not change when
  a file appears, so a session that started without `AGENTS.md` kept reporting
  that none existed even after `/init` wrote one. Discovery now re-runs while
  nothing has been found and stops costing anything once instructions exist.
- **The model catalog parses again, and a fork guarantee is back.** Upstream
  0.147.0 introduced its own legacy `base_instructions` layer: a top-level key
  in the catalog JSON, promoted into `model_messages.instructions_template` on
  read. Its serializer flattens `ModelInfo` and adds that key itself, so with
  the fork field also serialized the catalog carried `base_instructions` twice
  and failed to parse. Separately, the merge had taken upstream's
  `get_model_instructions()`, whose fallback branch returns an empty string
  where this fork returns `base_instructions` — every catalog entry without a
  template would have shipped with no instructions at all. The field is now
  outside serde and the fallback is restored, with a behavioural test that
  fails if the branch is ever emptied again.
- **Pairing says how to start the daemon** when none is listening, instead of
  failing on a missing socket.

## Retired

- **Patch #24 (Termux TLS roots).** Upstream removed the last `reqwest` client
  this crate built for itself, and `reqwest` left the crate's dependencies with
  it, so the guard no longer compiled. MCP OAuth discovery now runs on the
  injected `codex-http-client`, which never constructs the
  `rustls-platform-verifier` that panics on Android without a JVM context. The
  `verify-patches.sh` check is inverted rather than deleted: it now asserts that
  no direct `reqwest` dependency returns.

  This establishes that the panic is unreachable on that path. It does not
  establish that the replacement's native root store is populated under Termux;
  that has not been measured on a device.

## Verification

- `cargo check --workspace --all-targets`: clean.
- `cargo test -p codex-tui --lib`: 3399 passed, 0 failed.
- `cargo test -p codex-core --lib`: 2170 passed, 2 failed — both pre-existing and
  unrelated to this release: `post_sampling_token_estimate_is_disabled_by_always_on_sinks`,
  which fails inside the full suite and passes on its own, and
  `record_context_updates_emits_environment_item_for_time_changes`, an upstream
  test that only fails on a host whose timezone is `Europe/Berlin`: it sets the
  "new" timezone to the value the host already reports, so nothing changes and
  no environment item is emitted.
- `verify-patches.sh`: every fork patch present.
- Independently re-verified before release.
